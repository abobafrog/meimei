# Frokla

Статический интерфейс Frokla (HTML/CSS/JavaScript) сохранён. Сервер, API, мастерская и SQLite-логика реализованы на Rust с Axum, Tokio и rusqlite. Python используется отдельно только для обучения PyTorch-классификаторов и экспорта ONNX.

Прежняя Python-реализация сохранена в `legacy_python/` только для сверки и больше не используется для запуска сайта.

## Запуск

Нужны Rust/Cargo 1.85 или новее, CMake, C++-компилятор и библиотека ONNX Runtime для CPU. На macOS CMake можно установить через `brew install cmake`; на Ubuntu — через `sudo apt install build-essential cmake libclang-dev`. Сборка ограничена одним заданием Cargo, чтобы не перегружать машину с 4 ГБ памяти. При первом запуске Frokla скачает локальную языковую модель помощника (около 1,12 ГБ), проверит контрольную сумму и сохранит её в `models/assistant/`. Интернет нужен для первого скачивания. Если новая модель недоступна, сервер продолжит работу с прежней Qwen 0.5B, если она уже установлена. Файлы моделей не включены в Git; `cargo run --release -- setup-model` позволяет скачать и проверить актуальную модель заранее. Без ONNX-моделей послания остаются на ручной проверке; рисунки публикуются сразу.

```sh
cargo run --release
```

По умолчанию сервер слушает `127.0.0.1:4173` и раздаёт сайт из `dist`. Переменные окружения:

- `HOST`, `PORT` — адрес и порт; по умолчанию `127.0.0.1` и `4173`.
- `FROKLA_ROOT` — каталог проекта.
- `FROKLA_DB` — путь к SQLite; по умолчанию `canvas.sqlite3` в каталоге проекта.
- `FROKLA_STATIC_DIR` — каталог сайта; по умолчанию `dist`.
- `FROKLA_BACKUP_DIR` — каталог копий; по умолчанию `backups`.
- `TRUSTED_PROXIES` — доверенные IP/CIDR reverse proxy через запятую. Без этого `X-Forwarded-For` игнорируется.
- `GEOLOOKUP_ENABLED=0` — отключить внешнее определение примерной географии через `ipwho.is`.
- `ORT_DYLIB_PATH` — путь до `libonnxruntime.so`, когда установлены модели и динамическая библиотека не находится автоматически.

Для проверки/загрузки языковой модели отдельно:

```sh
cargo run --release -- setup-model
```

Команда скачивает Qwen2.5-1.5B-Instruct в формате GGUF Q4_K_M из [официального репозитория Qwen](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF), сохраняет её во временный файл и устанавливает только после проверки SHA-256. Модель распространяется по Apache-2.0. Для генерации Rust использует llama.cpp через `llama-cpp-2`: контекст ограничен 2048 токенами, ответ — 220 токенами, одновременно обрабатывается один запрос, задействуются два потока CPU. Помощник настроен на тексты открыток и новогодние поздравления: возвращает один готовый к отправке текст с уместными эмодзи и перенаправляет запросы на другие темы.

В мини-помощнике сообщение обрабатывается этой моделью на сервере Frokla и не отправляется во внешний AI API. Для защиты сервера ограничены длина вопроса и частота запросов с одного IP. Открытие сайта напрямую через `file://` не запускает модель — для неё нужен Rust-сервер.

Для публичного доступа оставьте Rust-сервер на loopback и поставьте перед ним HTTPS reverse proxy. Не публикуйте каталог проекта: статические файлы обслуживаются только из `dist`, SQLite и конфигурация мастерской остаются вне него.

## Закрытая мастерская

Если `.admin.json` уже существует, Rust использует его секретный путь, соль и PBKDF2-HMAC-SHA256 хеш пароля. Первый запуск без файла:

```sh
cargo run --release -- setup-admin
```

Ссылка и пароль будут записаны в `.admin-access.txt`; оба файла создаются только для владельца и исключены из Git. Сессия живёт восемь часов. Вход и операции используют проверку Origin, CSRF-токен и ограничение попыток пароля. Секретный путь не выводится в серверные логи.

Мастерская позволяет проверять послания, управлять рисунками целиком, публиковать открытки, смотреть карту посещений и статистику. Рисование остаётся мгновенно видимым на общем холсте. На первом визите создаётся случайный профиль браузера `frokla_visitor` — это не имя и не аккаунт. Рисунки связаны в группы по случайному ID, который живёт в браузере 15 минут после последнего штриха. В мастерской можно посмотреть все штрихи группы, одобрить или отклонить её целиком либо удалить рисунок и все его штрихи; в сводке профиля можно удалить сразу все его рисунки. Сводка показывает последний известный IP, время активности и число рисунков. Если за 90 дней профиль не возвращался и не владеет рисунками, его сводная запись очищается. IP посещений сохраняются в SQLite до 90 дней и показываются только в авторизованной мастерской. Полный User-Agent не сохраняется. Для приблизительной карты сервер передаёт публичный IP на `ipwho.is`; это отключается через `GEOLOOKUP_ENABLED=0`. Картографические тайлы запрашиваются браузером у OpenStreetMap только при открытой мастерской.

## Данные и резервные копии

При старте Rust сначала создаёт SQLite Online Backup существующей базы и только затем выполняет совместимые миграции `canvas.sqlite3` на месте: послания, статусы, избранное, штрихи, квоты, посещения и добровольные интересы сохраняют свои ID и значения. Новые таблица групп рисунков и поле `drawing_id` добавляются без очистки или пересоздания старых данных; старые штрихи связываются в группы по автору и 15-минутному окну, а без владельца остаются отдельными рисунками. Если предварительный снимок не удался, сервер не начинает миграцию. SQLite использует WAL, `synchronous=FULL`, ограниченное число блокирующих DB-задач и тайм-аут ожидания записи.

Файл базы по умолчанию — `canvas.sqlite3` в каталоге проекта; путь на сервере можно закрепить через `FROKLA_DB`. База, WAL-файлы и `/backups/` исключены из Git. Обычный `git pull` не заменяет базу и не удаляет резервные копии: не запускайте `git clean -x` и не меняйте `FROKLA_DB` между обновлениями. На Ubuntu оставьте базу на прежнем месте, остановите сервис на время `git pull`, затем запустите его снова. Первая версия с миграцией сохранит SQLite-снимок до изменения схемы.

После старта резервная копия создаётся сразу, затем — каждые шесть часов через SQLite Online Backup API; локально сохраняются 28 последних копий. Для копии на другом диске задайте `FROKLA_BACKUP_DIR` на подключённый носитель. Однократную копию можно создать командой:

```sh
cargo run --release -- backup
```

Перед восстановлением остановите сервер, сохраните повреждённую базу отдельно и проверьте целостность резервной копии. Не копируйте работающий WAL-файл как единственный backup обычной командой `cp`.

Для восстановления остановите службу и выполните:

```sh
cargo run --release -- restore /путь/к/frokla-1234567890.sqlite3
```

Команда повторно проверяет снимок и оставляет предыдущую целостную базу рядом с восстановленной под именем `*.pre-restore-*.sqlite3`.

## Локальная AI-модерация и обучение

В Git включена компактная ONNX-модель `local_ai/models/base-nsfw-384/drawing.onnx` с Apache-2.0. При наличии динамической библиотеки ONNX Runtime Rust загружает её с одним CPU-потоком. Она проверяет весь сгруппированный рисунок после паузы в 20 секунд и сохраняет только оценку-подсказку в мастерской. Модель определяет только NSFW-сигнал; она может ошибаться, поэтому не отклоняет и не удаляет рисунки автоматически. Рисунки остаются мгновенно видимыми, а решения принимает модератор. Если ONNX Runtime не установлен, сайт продолжает работать без AI-подсказки.

Для текущей версии ONNX сервер пересчитывает порог подсказки после каждой новой оценки целого рисунка, которую эта версия модели успела обработать. Нужны хотя бы по одному одобренному и отклонённому примеру; по мере накопления примеров подстройка плавно усиливается, а при малом наборе остаётся близко к исходному порогу. Решения и оценки остаются в SQLite; калибровка меняет только будущие подсказки, не удаляет рисунки и не заменяет решение человека. Весовые коэффициенты ONNX автоматически на сервере не переобучаются.

Для начальной выборки загружены 512 безопасных по тематике рисунков снежинок, снеговиков и деревьев из Google Quick, Draw! с CC BY 4.0. Это примеры эскизов, а не обучающий набор модерации: в них нет класса отклонённых рисунков, и Google предупреждает, что даже проверенные рисунки могут содержать неподходящий контент. Они нужны только как стартовые положительные примеры; реальное качество зависит от решений модераторов Frokla. Атрибуция и ограничения описаны в `local_ai/datasets/README.md`.

Собирайте обучающий набор на Mac или другой машине с памятью, не на 4-ГБ Ubuntu. Создайте локальные папки `local_ai/dataset/allowed/` и `local_ai/dataset/rejected/` и положите туда изображения, уже проверенные человеком. Они исключены из Git. Решения по целым рисункам можно экспортировать из SQLite:

```sh
cargo run --release -- export-training /tmp/frokla-decisions.jsonl
```

Установите зависимости и дообучите модель:

```sh
python3 -m venv .venv
.venv/bin/pip install -r local_ai/requirements.txt
.venv/bin/python local_ai/train_vision.py --export /tmp/frokla-decisions.jsonl --epochs 4 --batch-size 2
```

Тренер берёт только рисунки, уже целиком подтверждённые в мастерской, и требует не менее 20 примеров в каждом классе. Он дообучает последние блоки базовой ViT-модели Marqo, проверяет ONNX-файл локальным ONNX Runtime и переключает `current.json` только после успешной проверки. Установщик загружает исходные веса Marqo с Hugging Face при первом запуске тренировки. Оценка на маленькой отложенной выборке не гарантирует качество на реальном сайте; оставьте AI только подсказчиком.

Предобученная ONNX-модель и открытая выборка идут в Git. Личные картинки, экспорт из БД, пользовательские обученные веса и `current.json` исключены. Если дообученную модель нужно перенести на Ubuntu, скопируйте её версионную папку и соответствующий `current.json` отдельно; обновление кода через Git при этом не трогает SQLite и её бэкапы.

Локальный режим `file://` остаётся отдельным: он хранит данные в `localStorage`, включая тестовые послания, и не синхронизируется с серверной базой.
